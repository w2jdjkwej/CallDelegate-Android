# 已知限制

## 源码快照边界

公开仓库不包含模型权重、AAR、APK、scrcpy-server、录音和设备测试产物。未准备本地资源时，部分功能只能阅读或编译，不能完成真实语音推理。

## 语音与规则

- 能量 VAD 对噪声、远场和说话停顿较敏感；
- Vosk 与 VITS 的准确率、延迟、内存和稳定性取决于设备与音频条件；
- 规则 NLU 和 JSON 状态机只覆盖有限场景，不是开放式聊天模型；
- 模拟输入和文本测试不能替代真实麦克风、真实通话或目标设备验收。

## Android 通话能力

- 默认拨号器和 Android Telecom API 不等于获得运营商通话的双向 PCM；
- Shizuku/scrcpy 方案依赖 shell 权限、隐藏 API、Android 版本和厂商音频策略；
- 设备侧成功写入或播放 PCM 不能单独证明远端参与者听见了 TTS；
- 蓝牙、保持、切换、来电、去电和长通话需要分别验证。

## 数据与合规

- 会话数据保存在应用私有目录和 Room，但当前没有额外的文件加密层；
- 进程被系统强制终止时，最后一轮数据可能无法完整提交；
- 录音、转写、提示和保存期限必须根据使用地区、参与者所在地及具体用途评估；
- 本项目不声明默认配置在所有国家和地区均合规。

## 证据口径

应分别记录以下结果，不能相互替代：

1. 源码实现存在；
2. JVM 或静态检查通过；
3. APK 构建成功；
4. Android 仪器测试执行；
5. 真实设备和真实通话结果；
6. 远端参与者实际听见音频的独立确认。

没有执行的项目应明确标记为 `NOT_RUN`，测试跳过不应表述为通过。
