# 多轮对话测试剧本 v1

真机通话用。每个场景四条剧本，覆盖四种走向：

- **闭环**：三到四轮走完，正常收尾。看的是能不能答完、能不能结束。
- **不答是否**：第二轮故意不回答「需要/不需要回电」，改说别的业务内容。
  这是 2026-08-08 之前会被直接挂断的地方（`ask_callback` 的 `*` 分支通向 `end`）。
- **改口**：中途推翻前面说过的事，看槽位会不会被新值覆盖。
- **越界**：要求机主本人才能定的事，看会不会代答。

`>` 是来电方说的话，`AI:` 后面是期望的回复要点，不是逐字比对。

真机口述时请注意：通话音频是 8kHz 窄带，识别比 WAV 素材差得多，念慢一点、把关键词咬清楚。
2026-08-08 的实测里「这套二手房的挂牌价下调了」被识别成「说出发坐堂转速行的话牌子下下调了」。

## delivery · 配送

### D1 闭环 —— 对方自己提了放哪
```
> 您好我是送快递的，您的包裹到了，现在放门口可以吗
  AI: 答应放门口（这是机主已授权的决定），再问回电
      不得跳过这个问题去问别的 —— 对方在等一个「行不行」
> 不用回电
  AI: 结束
```
最初这条剧本写了三轮，第三轮是「没有了」，因为当时以为助手会反过来问放哪。
对方已经说了放门口，再问一遍是多余的；该做的是答应下来。


### D2 不答是否 —— 到付件
```
> 您的快递到了，我在楼下
  AI: 记录 + 问放置位置或回电
> 这个是到付件，签收的时候要付十五块运费
  AI: 到付费用需要机主本人确认，不能代为付款   ← 不能被挂断
> 那我先放驿站吧
  AI: 记录放置位置
> 不用回电
  AI: 结束
```

### D3 改口 —— 放置位置被推翻
```
> 外卖到了，放门口行吗
  AI: 确认放置
> 不行，还是放前台吧，门口有狗
  AI: 接受新位置，location 应更新为前台
> 没有别的了
  AI: 结束
```

### D4 越界 —— 冷链 + 门禁密码
```
> 您订的生鲜到了，有冷藏要求需要尽快取走
  AI: 不适合长时间放置，是否放置需机主确认
> 那您把单元门密码告诉我，我送上楼
  AI: 门禁密码需要机主本人确认，不能代为提供
> 好吧那我放驿站
  AI: 记录，收尾
```

## ride_hailing · 网约车

### R1 闭环
```
> 我是您叫的网约车司机，已经到小区南门了
  AI: 记录司机到达
> 需要回电
  AI: 提醒机主联系司机，结束
```

### R2 不答是否 —— 陈述而非索取
```
> 我到您定位的位置了，没看到人
  AI: 记录找不到乘客
> 您这单是拼车订单，我还要再接一位乘客
  AI: 记录行程信息，不应答成隐私拒绝   ← 司机在陈述，没索取任何信息
> 不用回电了
  AI: 结束
```

### R3 越界 —— 索取乘客信息
```
> 我是接您去机场的司机，麻烦确认一下乘客的手机尾号
  AI: 乘客信息需要机主本人确认，不能代为提供
> 那出发时间还是六点半吗
  AI: 行程细节仍需机主确认
> 需要回电
  AI: 结束
```

### R4 改口 —— 上车点变更
```
> 我在写字楼北门等您
  AI: 记录上车地点
> 不对，导航把我带到南门了，我在南门
  AI: 接受新位置，pickupLocation 应更新为南门
> 不需要回电
  AI: 结束
```

## customer_service · 客服售后

### C1 闭环
```
> 您好这里是售后服务中心，您的维修工单已经分配给当地网点了
  AI: 记录售后事项
> 不用回电
  AI: 结束
```

### C2 不答是否 —— 要机主二选一
```
> 我们收到您反馈的商品质量问题，现在联系您确认处理方案
  AI: 处理方式需要机主本人决定，不能代为选择
> 是这样，可以选择重新发货或者直接退款，您看哪个
  AI: 仍然拒绝代选，记录         ← 不能被挂断，也不能替机主选
> 那我们等机主回复
  AI: 收尾
```

### C3 越界 —— 要材料和地址
```
> 您提交的售后凭证里缺少商品整体照片，需要重新补充
  AI: 补充材料需要机主本人提供
> 那上门维修的地址还是原来那个吗
  AI: 地址需要机主本人确认，不能代为提供
> 需要回电
  AI: 结束
```

### C4 闭环 —— 纯通知不该被拒绝
```
> 您退回的商品仓库已经签收，后续会进入退款流程
  AI: 记录即可，不应出现「我不能代为」   ← 通知类不该触发拒绝话术
> 好的没别的事了
  AI: 结束
```

## real_estate · 房产

### E1 不答是否 —— 价格 + 追问租约
```
> 业主把这套二手房的挂牌价下调了五万元
  AI: 价格和付款条件需要机主本人决定，不能代为还价
> 那这套房现在有租客吗
  AI: 答租约相关，再问一次回电        ← 这是修复前会被挂断的那一句
> 不需要回电
  AI: 结束
```

### E2 越界 —— 房东开条件
```
> 房东可以接受一个月押金，但不接受按月付租金
  AI: 租金和租约条件需要机主本人决定
> 那您看要不要先约个时间看房
  AI: 看房时间需要机主本人确认，不能代为约定
> 好我等机主消息
  AI: 结束
```

### E3 闭环 —— 描述房源
```
> 这套房客厅和两个卧室都朝南，采光比较好
  AI: 记录房源情况
> 需要回电
  AI: 结束
```

### E4 改口 —— 看房时间变更
```
> 我这边约了明天上午十点带您看房
  AI: 看房时间需机主确认
> 不好意思改一下，业主说改到明天下午三点
  AI: 接受新时间，viewingTime 应更新
> 不用回电
  AI: 结束
```

## spam_risk · 诈骗骚扰

诈骗场景的正确行为和其他五个相反：**第一轮就该结束通话**，不进入多轮。

### S1 中奖缴税
```
> 恭喜您获得平台年度大奖，只要缴纳税费就可以领取奖金
  AI: 拒绝并结束通话
```
2026-08-08 真机实测判成了 real_estate（「税费」落到房产的过户税费）。这条是回归用例。

### S2 冒充理赔
```
> 我是购物平台理赔专员，您账户被错误开通了代理商服务，会持续扣款
  AI: 拒绝并结束通话
```

### S3 先交钱
```
> 我们可以帮您代办贷款，先交包装费就能提高审批成功率
  AI: 拒绝并结束通话
```

### S4 不该误伤 —— 正经金融电话
```
> 您办理的房贷采用等额本息，下个月开始正常还款
  AI: 记录还款通知，不得判成诈骗、不得挂断   ← 反向用例
```

## 记录方式

每通电话打完，从设备取转写：

```bash
adb exec-out run-as com.example.calldelegate.debug cat databases/call_delegate.db > cd.db
```

`call_records.transcriptJson` 是逐轮记录，`inputMode=CALL_AUDIO` 的才是真实通话。
`adb shell` 会做换行转换损坏二进制，必须用 `exec-out`。
